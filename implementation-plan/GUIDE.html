1. The Business Problem & Enterprise Need

The $400B Back-Office Problem in BFSI

Banks, insurance companies, and financial services firms spend $400+ billion annually on back-office operations — manual, repetitive, rule-heavy tasks performed by humans navigating legacy systems. These operations are:

🏦 What Operations Teams Do Today

  • Invoice Reconciliation: Manually download bank statements, cross-reference against ERP invoices, identify mismatches, post journal entries — 2-4 hours daily per analyst
  • KYC Verification: Navigate 5-8 different portals to verify customer identity, check sanctions lists, compile evidence packages — 45 min per case
  • Loan Operations: Pull credit reports, verify collateral documents, update lending CRM, generate compliance letters — 30 min per application
  • Regulatory Filing: Extract data from multiple systems, transform into regulatory format, validate against rules, submit to portals — days per filing cycle

💸 Why This Costs So Much

  • Labor cost: $35-75/hour fully-loaded per operations analyst
  • Error rate: 2-5% manual error rate → costly corrections, regulatory fines
  • Legacy systems: No APIs — humans must navigate browser UIs on 15-20 year old ERPs
  • Compliance burden: Every action must be auditable for 7+ years (SOC 2, SOX, Basel III)
  • Scale ceiling: Hiring more analysts is linear cost; volume grows exponentially

Why Existing Solutions Fail

ApproachWhy It Fails for BFSI
Traditional RPA (UiPath, Blue Prism)Brittle selectors break on UI changes. No reasoning — cannot handle exceptions. No audit trail that satisfies regulators. $150K+ per bot license.
API IntegrationLegacy banking portals and ERPs (built 2005-2010) have no usable APIs. Integration projects take 12-18 months and $2M+.
Single-Model AI AgentsUsing one LLM for both reasoning AND UI execution is either too expensive ($3+/run) or too unreliable (UI agent making policy decisions).
Offshore BPOStill manual, still error-prone, adds data residency risk, 6-month ramp-up per process.

What BackOfficePilot Solves

Core Insight: Back-office work naturally splits into reasoning (interpret policy, classify exceptions, make decisions) and execution (click buttons, fill forms, download files). Using two specialized AI models — one for each — delivers 10× cost reduction with audit-grade reliability.

2. Project Overview

What is BackOfficePilot?

A multi-model agentic automation platform for BFSI back-office. Two AI models collaborate through a deterministic orchestrator:

10 PERC Loop ⭐ (STORY-A3-010) — Days 9-11

CRITICAL PATH. This is the core orchestration engine.
class PERCLoop:
    async def run(self, workflow, plan) -> RunResult:
        for step in plan.steps:
            if await self._is_aborted(run_id): break    # abort signal
            if self.cost_ceiling.is_breached(): break    # cost ceiling

            result = await self.executor_router.execute(step)
            decision = await self.reasoner.reconcile(result, policy)

            if decision.is_exception:
                exception = self.classifier.classify(decision, step)
                if step.retry_count >= max_retries:
                    await self._escalate(exception); break

            await self.event_bus.emit(StepExecuted(step, result))
        await self.event_bus.emit(RunCompleted(run))

Verify: 5-step workflow completes. Retry, ceiling, abort all work. Hypothesis passes.

8. Development Methodology

2. WRITE BDD         → features/BDD-{story-id}.feature

11. Key Design Patterns

Hexagonal Architecture

Domain (pure) ← Ports (interfaces) ← Adapters (AWS implementations)

  • Domain has NO external dependencies
  • Ports are abstract base classes
  • Adapters implement ports — swap for testing

Event-Driven Internal Bus

Every state transition emits a domain event: PlanCreated → StepExecuted → ExceptionRaised → RunCompleted → CostMetered

Subscribers (audit, cost, escalation) are independent and decoupled.

Snapshot Semantics

Run records workflow + policy bundle hashes at start. Executes against that snapshot forever, even if config changes mid-run.

Cost Ceiling Enforcement

Soft ceiling: max_cost_per_run_usd (default $1.00). Hard ceiling: 2× soft (kill switch). Checked between every step.
