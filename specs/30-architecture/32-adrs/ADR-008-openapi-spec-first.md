# ADR-008: OpenAPI 3.1 spec-first API contract

## Context

The Next.js frontend consumes a TypeScript client of the Python backend. FastAPI can generate
OpenAPI from Pydantic models (code-first), or we can hand-author the OpenAPI document and
generate both server stubs and client (spec-first).

In a spec-driven development repo (`ADR-003`), code-first contradicts the discipline: the code
becomes the source of truth, not the spec.

## Decision

The file **`30-architecture/34-api-contract/openapi.yaml`** is the authoritative API contract.

- FastAPI route signatures and Pydantic models are generated from it (`datamodel-code-generator`
  for models; thin handwritten routers that import and use them).
- The Next.js TypeScript client is generated from it (`openapi-typescript` and
  `openapi-fetch`).
- Both code paths are regenerated by `make codegen`. Generated files are committed but never
  edited by hand. CI fails if `git diff` after `make codegen` is non-empty.

## Alternatives considered

- **Code-first FastAPI**: faster bootstrap; weaker contract guarantee; spec lags reality.
- **gRPC / Connect**: stronger contracts, but adds tooling, and the frontend story is worse for
  REST-style admin operations.
- **GraphQL**: appealing for the dashboard, but unnecessary complexity for the surface we have.

## Consequences

**Positive**

- Contract changes are reviewable as a single PR to one file.
- Type safety across frontend and backend.
- API documentation is the same artifact every reader uses.

**Negative**

- Adds a `make codegen` step to the developer loop.
- Pydantic features that escape OpenAPI (validators, discriminators in some edge cases) require
  care.
- Generators occasionally produce ugly code; we accept it and never edit.

## Conventions

- OpenAPI document uses `info.version` semver.
- Every operation has an `operationId` in `camelCase`, matching the generated client method name.
- Schemas use `PascalCase`. Reusable enums declared once at the top.
- Errors follow a single envelope schema (`Problem` per RFC 9457).
